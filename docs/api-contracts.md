# API-контракты

Система краткосрочного прогнозирования погоды. Спринт 3.

Базовый путь: `/api/v1`. Формат обмена: JSON, кодировка UTF-8. Все метки времени в ISO 8601 с указанием смещения.

## Общие правила

| Код | Когда возвращается |
|---|---|
| 200 | Запрос выполнен, тело содержит результат |
| 201 | Создан новый ресурс (построен и сохранён прогноз) |
| 400 | Некорректный формат параметра (дата не разбирается, горизонт не число) |
| 404 | Город или модель с указанным идентификатором отсутствует |
| 409 | Прогноз с такой комбинацией города, модели и моментов уже существует |
| 422 | Параметры корректны по типу, но недопустимы по смыслу (начало периода позже конца) |
| 500 | Внутренняя ошибка, в том числе недоступность внешнего источника |

Тело ошибки единообразно:

```json
{
  "detail": "City with id 7 not found"
}
```

## 1. Список городов

`GET /api/v1/cities`

Закрывает ФТ-5. Параметров не принимает: список фиксирован при инициализации (ФТ-4).

Ответ 200:

```json
[
  {
    "city_id": 1,
    "name": "Алматы",
    "latitude": 43.2567,
    "longitude": 76.9286,
    "timezone": "Asia/Almaty",
    "elevation_m": 800.0
  },
  {
    "city_id": 2,
    "name": "Астана",
    "latitude": 51.1694,
    "longitude": 71.4491,
    "timezone": "Asia/Almaty",
    "elevation_m": 350.0
  }
]
```

## 2. История наблюдений

`GET /api/v1/cities/{city_id}/observations`

Закрывает ФТ-6 и ФТ-7.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `from` | datetime | да | Начало периода включительно |
| `to` | datetime | да | Конец периода включительно |

Ответ 200:

```json
{
  "city_id": 1,
  "count": 168,
  "observations": [
    {
      "observed_at": "2026-10-01T00:00:00+05:00",
      "temperature_c": 12.4,
      "humidity_pct": 58.0,
      "pressure_surface_hpa": 921.3,
      "pressure_msl_hpa": 1014.2,
      "precipitation_mm": 0.0
    }
  ]
}
```

Ошибки: 404 если города нет, 422 если `from` позже `to`.

## 3. Построение прогноза

`POST /api/v1/cities/{city_id}/forecasts`

Закрывает ФТ-8, ФТ-9, ФТ-10, ФТ-11. Строит прогноз на каждый час до указанного горизонта и сохраняет все значения в базу.

Тело запроса:

```json
{
  "model": "linear_regression",
  "version": "v1",
  "max_horizon_hours": 48
}
```

Ответ 201:

```json
{
  "city_id": 1,
  "model": "linear_regression",
  "version": "v1",
  "created_at": "2026-10-08T11:00:00+05:00",
  "stored": 48,
  "forecasts": [
    {
      "target_time": "2026-10-08T12:00:00+05:00",
      "horizon_hours": 1,
      "predicted_temperature_c": 14.8
    }
  ]
}
```

Поле `stored` содержит количество записей, фактически вставленных в базу. Ошибки: 404 если город или модель не найдены, 409 при повторном запуске с тем же моментом построения, 422 если горизонт вне диапазона от 1 до 48.

## 4. Получение прогноза

`GET /api/v1/cities/{city_id}/forecasts`

Закрывает ФТ-12. Возвращает последний построенный прогноз для отображения на графике.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `model` | string | нет | Имя модели, по умолчанию `linear_regression` |
| `created_at` | datetime | нет | Конкретный запуск; при отсутствии берётся последний |

Ответ 200 по структуре совпадает с телом ответа на построение прогноза, но без поля `stored`.

## 5. Метрики точности

`GET /api/v1/metrics`

Закрывает ФТ-13, ФТ-14, ФТ-15, ФТ-16. Сопоставляет сохранённые прогнозы с фактическими наблюдениями и возвращает агрегированные показатели.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `city_id` | int | нет | Фильтр по городу; без него по всем |
| `horizon_hours` | int | нет | Фильтр по горизонту |
| `from` | datetime | нет | Нижняя граница целевого момента |
| `to` | datetime | нет | Верхняя граница целевого момента |

Ответ 200:

```json
{
  "filters": { "city_id": 1, "horizon_hours": 24 },
  "models": [
    {
      "model": "seasonal_naive",
      "version": "v1",
      "matched_pairs": 720,
      "mae": 2.41,
      "rmse": 3.12,
      "ratio_to_baseline": 1.0
    },
    {
      "model": "linear_regression",
      "version": "v1",
      "matched_pairs": 720,
      "mae": 1.93,
      "rmse": 2.55,
      "ratio_to_baseline": 0.80
    }
  ]
}
```

Поле `matched_pairs` показывает, сколько прогнозов удалось сопоставить с фактом. Прогнозы, для которых наблюдение ещё не поступило, в расчёт не входят.

## 6. Деградация точности по горизонту

`GET /api/v1/metrics/by-horizon`

Закрывает ФТ-17. Возвращает ошибку для каждого горизонта от 1 до 48, что даёт кривую деградации точности.

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `city_id` | int | нет | Фильтр по городу |
| `model` | string | нет | Имя модели |

Ответ 200:

```json
{
  "city_id": 1,
  "model": "linear_regression",
  "points": [
    { "horizon_hours": 1,  "mae": 0.84, "rmse": 1.12, "matched_pairs": 720 },
    { "horizon_hours": 24, "mae": 1.93, "rmse": 2.55, "matched_pairs": 720 },
    { "horizon_hours": 48, "mae": 2.67, "rmse": 3.41, "matched_pairs": 695 }
  ]
}
```

## 7. Загрузка данных

`POST /api/v1/cities/{city_id}/observations/load`

Закрывает ФТ-1, ФТ-2, ФТ-3. Служебный эндпоинт: обращается к внешнему источнику и сохраняет наблюдения.

Тело запроса:

```json
{
  "from": "2023-10-01",
  "to": "2026-10-01"
}
```

Ответ 200:

```json
{
  "city_id": 1,
  "received": 26304,
  "inserted": 26100,
  "updated": 204
}
```

Разделение на `inserted` и `updated` подтверждает работу защиты от дублирования: повторный запуск того же периода даёт `inserted` равным нулю.

Ошибки: 404 если города нет, 500 при недоступности внешнего источника.

| Эндпоинт | Покрывает |

| `POST /cities/{id}/forecasts` | ФТ-8, ФТ-9, ФТ-10, ФТ-11 |
| `GET /cities/{id}/forecasts` | ФТ-12 |
| `GET /metrics` | ФТ-13, ФТ-14, ФТ-15, ФТ-16 |
| `GET /metrics/by-horizon` | ФТ-17 |
| `POST /cities/{id}/observations/load` | ФТ-1, ФТ-2, ФТ-3 |

Все семнадцать функциональных требований спецификации покрыты.
