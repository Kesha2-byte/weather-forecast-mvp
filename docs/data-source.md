# Источник данных

Первичная проверка: 02.09.2026, скрипт `scripts/check_data_source.py`.
Полная загрузка истории: 13.10.2026, скрипт `scripts/load_observations.py`.

## Провайдер

Open-Meteo. Ключ API и регистрация не требуются, бесплатно для некоммерческого использования.

Используются два эндпоинта:

| Эндпоинт | URL | Назначение |
|---|---|---|
| Historical Weather API | `https://archive-api.open-meteo.com/v1/archive` | Глубокий архив для обучения модели |
| Forecast API | `https://api.open-meteo.com/v1/forecast` | Свежие факты (`past_days`) для сравнения с прогнозом |

## Разрешение и глубина

- Шаг: 1 час, подтверждён (168 точек за 7 суток).
- Архив: данные доступны с 1940 года. Первая доступная дата возвращает `None`, со второй данные есть.
- Задержка архива: 1 день (проверка от 02.09.2026, последний доступный день 01.09.2026).
- Forecast API с `past_days=7` перекрывает разрыв между архивом и текущим моментом.

## Поля

Запрашиваются через параметр `hourly`, пропусков на тестовой выборке нет.

| Поле | Единица | Комментарий |
|---|---|---|
| `temperature_2m` | °C | Целевая переменная прогноза |
| `relative_humidity_2m` | % | Только хранение и аналитика |
| `surface_pressure` | гПа | Давление на уровне поверхности, зависит от высоты станции |
| `pressure_msl` | гПа | Давление, приведённое к уровню моря |
| `precipitation` | мм | Сумма за предшествующий час |

Формат ответа: объект `hourly` содержит массив `time` и параллельные массивы значений одинаковой длины. При загрузке в БД сшиваются по индексу.

## Загруженный объём

Период: 2023-10-01 .. 2026-10-01, оба города.

| Город | Записей | Первая | Последняя |
|---|---|---|---|
| Алматы | 26 328 | 2023-10-01 00:00 | 2026-10-01 23:00 |
| Астана | 26 328 | 2023-10-01 00:00 | 2026-10-01 23:00 |

Период составляет 1097 суток, что при часовом шаге даёт ровно 26 328 записей. Фактическое количество совпадает с расчётным, следовательно пропусков в ряду нет.

При загрузке Алматы 720 записей были обновлены, а не вставлены: они относятся к сентябрю 2026 и попали в базу ранее при проверке загрузчика. Это подтверждает работу защиты от дублирования на полном объёме данных.

## Принятые решения

**Глубина загрузки - 3 года.** Архив уходит до 1940 года, но данные середины XX века для краткосрочного прогноза бесполезны и смещают модель. Три года часовых наблюдений дают около 26 тысяч записей на город, суточный цикл повторяется более тысячи раз, годовой - трижды.

**Давление.** `surface_pressure` не приведено к уровню моря и зависит от высоты точки: для Алматы (около 800 м) типичное значение ~920 гПа против ~1013 на уровне моря. Для сопоставимости городов дополнительно хранится `pressure_msl`.

**Обработка пропусков.** `None` в ответе возможен на границах архива, загрузчик обязан их переживать без остановки.

## Неоднородность ряда: переход часового пояса

При загрузке трёхлетней истории обнаружен разрыв, вызванный переходом Казахстана на единое время 1 марта 2024 года.

Наблюдения вокруг перехода (Алматы):

```
2024-02-29 22:00:00+06   -9.10
2024-02-29 23:00:00+05   -4.50
2024-03-01 00:00:00+05   -8.30
```

Локальные метки времени идут непрерывно, однако смещение меняется с +06 на +05. В абсолютном времени шаг между соседними записями составляет два часа вместо одного: один час (17:00 UTC 29.02.2024) в ряду отсутствует. Аномальное значение -4.50 на границе подтверждает артефакт: соседние значения образуют монотонный ночной спад, в который оно не укладывается.

Количество записей при этом полное, по 24 на сутки, поскольку провайдер возвращает полный набор локальных меток.

**Принятое решение: данные используются без коррекции.**

Обоснование. Смещение затрагивает лаговые признаки только у записей, пересекающих границу перехода: при лагах 24 и 48 часов это около 72 записей из 26 328, то есть менее 0,3 % выборки. Влияние на метрики качества пренебрежимо мало.

Рассмотренные альтернативы:

- Исключение окна в одни сутки до и после перехода (48 записей). Отклонено: сокращает обучающую выборку без измеримого выигрыша.
- Формирование лагов по фактической разности временных меток вместо смещения по номеру строки. Отклонено для MVP: существенно усложняет модуль признаков при нулевом практическом эффекте.

Второй вариант остаётся резервным, если влияние окажется заметным при оценке точности.

## Открытые вопросы

- Historical Weather API комбинирует несколько источников (ERA5 с 1940, ERA5-Land с 1950, ECMWF IFS с 2017). Разрыв на границе источников внутри загруженного периода не обнаружен, но отдельная проверка не проводилась.
- Ограничения на частоту запросов при массовой загрузке не проверялись. Загрузка трёх лет одним запросом на город прошла без ошибок.
